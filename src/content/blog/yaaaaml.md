# Разбор этого файла простыми словами

Этот файл — **инструкция для GitHub**, которая говорит: *«когда я закину новый код в проект, автоматически собери мой сайт на Astro и выложи его в интернет на GitHub Pages»*.

Такие файлы лежат в проекте по пути `.github/workflows/любое_имя.yml`.

Давай по строчкам.

---

## Самое начало

```yaml
name: Deploy Astro to GitHub Pages
```
Это просто **название** всей инструкции. Появится в интерфейсе GitHub во вкладке Actions. Ни на что не влияет.

```yaml
on:
  push:
    branches: [main]
```
Это **«когда запускать»**. Перевод: «запускай всё, что ниже, **когда в ветку `main` кто-то делает push**» — то есть когда ты загружаешь новые изменения в главную ветку.

```yaml
permissions:
  contents: read
  pages: write
  id-token: write
```
Это **«что разрешено делать»**. GitHub по умолчанию даёт мало прав — тут мы явно просим:
- читать код проекта,
- записывать в Pages (публиковать сайт),
- использовать токен для авторизации.

Без этого шаг с публикацией упадёт с ошибкой «нет прав».

---

## Раздел `jobs:` — самое главное

**Job** = отдельная «работа» (задача). У нас их две: `build` (собрать) и `deploy` (опубликовать).

Почему две? Потому что сначала нужно **собрать сайт**, а только потом **выложить результат**. Нельзя выложить то, чего ещё нет.

---

### Job №1 — `build`

```yaml
build:
  runs-on: ubuntu-latest
```
`runs-on` — **на какой машине это выполнять**. GitHub даёт бесплатный виртуальный компьютер (сервер) с Ubuntu. Всё, что ниже, происходит на нём.

```yaml
  steps:
```
**Шаги** — список действий по порядку. Как рецепт: сделай это, потом то.

```yaml
    - uses: actions/checkout@v4
```
**Скачай код** из твоего репозитория на этот виртуальный компьютер. Без этого шага там будет пусто.

`uses:` значит «используй готовое действие от GitHub». `actions/checkout@v4` — официальное действие, которое копирует твой код.

```yaml
    - uses: actions/setup-node@v4
      with:
        node-version: 20
```
**Установи Node.js версии 20**. Node нужен, чтобы запускать `npm`.

`with:` — это параметры для действия (что именно ему передать).

```yaml
    - run: npm install
```
**Выполни команду** `npm install` — установи все библиотеки проекта (те, что в `package.json`).

```yaml
    - run: npm run build
```
**Выполни `npm run build`** — собери сайт Astro. Astro возьмёт твои файлы и превратит их в готовые HTML/CSS/JS. Результат обычно оказывается в папке `dist/`.

```yaml
    - uses: actions/upload-pages-artifact@v3
      with:
        path: ./dist
```
**Загрузи папку `dist`** как «артефакт» — временный файл, который передадим в следующую работу (`deploy`). Без этого второй job не увидит результат сборки.

---

### Job №2 — `deploy`

```yaml
deploy:
  environment:
    name: github-pages
    url: ${{ steps.deployment.outputs.page_url }}
```
Указывает, что публикуем **в окружение GitHub Pages**.

`${{ ... }}` — **подстановка значения** (как переменная). Здесь: «возьми URL сайта, который вернёт шаг с id `deployment`, и запиши сюда». Это нужно, чтобы GitHub показал тебе ссылку на готовый сайт.

```yaml
  needs: build
```
**«Жди, пока закончится job `build`»**. Так `deploy` не запустится раньше сборки.

```yaml
  runs-on: ubuntu-latest
```
Снова свежая виртуалка с Ubuntu. (Да, отдельная — артефакт из первой job нужно специально передавать, поэтому и есть `upload-pages-artifact`.)

```yaml
  steps:
    - id: deployment
      uses: actions/deploy-pages@v4
```
**Единственный шаг**: официальное действие, которое берёт артефакт (папку `dist`, загруженную в `build`) и **публикует его на GitHub Pages**.

`id: deployment` — имя для этого шага, чтобы потом сослаться на него в `${{ steps.deployment.outputs.page_url }}` выше.

## Как это всё работает вместе — по шагам

1. Ты пишешь код и делаешь `git push` в `main`.
2. GitHub видит триггер `on: push` → запускает workflow.
3. Запускается job **build**: скачивает код → ставит Node → ставит зависимости → собирает сайт → загружает результат как артефакт.
4. Как только build закончился успешно, стартует job **deploy**.
5. Deploy берёт артефакт и выкладывает на GitHub Pages.
6. Через минуту-две твой сайт доступен по ссылке вида `https://твой_ник.github.io/имя_репозитория/`.

## Аналогия

Представь, что ты **заказал пиццу**:

- `on` — «когда позвоню, тогда и готовьте».
- `permissions` — «разрешаю вам пользоваться моей кухней и упаковкой».
- `jobs.build` — кухня: замесить, испечь, упаковать в коробку (`upload-pages-artifact` = положить коробку на выдачу).
- `jobs.deploy` — курьер: берёт коробку и везёт клиенту (GitHub Pages).
